# 無料・OSS 化と機能変更 (2026-11-13 方針決定・未実装)

Hayate を「Apple Watch で思いついたことを手放しで記録し、必要なサービスへ渡せる無料の OSS アプリ」にする。
アプリ単体の売上より、広く使われることと作者の GitHub での認知・フォロワー獲得を優先する。
外部連携なしでもメモ・リマインダーとして使え、詳しい人は Webhook で自分の環境につなげる。

これまでの課金の設計 (7 日間お試し + 買い切り) は [BILLING.md](BILLING.md) に残すが、**この方針で廃止**する。
実装・公開・ストア提出はまだ。決まっていないことは末尾の「未決事項」。

## 守る操作 (ユーザー確認済み)

左手のジェスチャーでアプリを選ぶ → 起動後のダブルタップで入力欄 → 音声入力 → 追加。
この流れに確認画面や送り先の選択を**増やさない**。Siri (`SendTextIntent`) も同じ扱い (メモ保存 + 有効な連携全部)。

## 入力とメモ

- 入力した内容はまず端末に保存する。外部への送信が失敗しても内容は失わない
- 外部連携を 1 つも設定しなくてもメモとして使える
- 入力確定前は直せる。**保存後の編集はしない**
- 時計のメモを iPhone で見られる
- 保存済みメモ: 閲覧・コピー・共有 (iPhone の共有シート)・削除
- メモごとに、後から登録済みの Webhook へ送れる

## 複数の送り先への連携

入力時に送り先を 1 つ選ぶ方式をやめ、iPhone で有効にした Webhook 全部へ送る。Slack・Discord の定型は残す。

- メモ保存と外部連携は併用できる
- 連携先ごとに 待機・完了・失敗 を持つ。一部が失敗しても他を止めない
- 再試行は未完了の連携だけ
- 画面では「入力を保存した」と「外部への送信が終わった」を分けて見せる
- Webhook の再送は同じメッセージ ID (`X-WatchHook-Message-Id`) で送る。受け手が重複を除かない場合の完全な重複防止は保証しない (README に書く)
- 送信は時計から直接 ([DESIGN.md](DESIGN.md) の「送信: 時計から直接」は変えない)

## iOS リマインダー連携

初版から、文頭の合図でリマインダーに追加する。例: 「リマインダー、牛乳を買う」

- 元の入力はそのままメモに保存する
- 文頭の「リマインダー」を除いた内容を、指定したリストに追加する。有効な Webhook への送信も併用
- 初回の設定で: 機能の有効化・アクセス許可・保存先リストの選択。通常の追加時には権限確認・編集画面を出さない
- 初版は期限なしのタスク。日時の自然言語解析はしない
- 時計 → iPhone に内容を送り、**iPhone 側で保存**する (時計の EventKit には頼らない)
- iPhone に届かなければ待機。保存が終わる前に成功扱いにしない
- 再試行で二重に追加しない

実機で確かめること (リマインダーへの裏での保存): 画面オフ・アプリ非表示 / 強制終了・再起動・切断 → 再接続・権限の取り消し。

## リマインダー以外の連携 (初版)

- **Markdown ファイルへの追記**: iCloud Drive の中からユーザーが選んだフォルダ (Obsidian の保管庫など) にある日付ごとのファイルへ、1 件 1 行で追記する。iPhone 側で保存する (リマインダーと同じく時計 → iPhone へ送り、保存し終わるまで成功扱いにしない)。
  フォルダはドキュメントピッカーで選び、security-scoped bookmark で覚える。ファイル名・行の書式・裏で書けるか (iCloud Drive のファイルが手元に無いとき・ロック中) は実装時に決めて確かめる
- **Webhook のプリセットを増やす**: Slack・Discord に加えて Notion・Todoist・ntfy・Telegram・Google Chat・Teams・n8n・Home Assistant など。本文テンプレートと案内だけで足りるもの。
  Todoist は日時を Todoist 側で解釈するので、日付付きのタスクが欲しい人にはこれを案内する

### 見送ったもの (2026-11-13)

- **カレンダー**: 入力の書き方がばらばらで難しい。次の版で、OS 内蔵の日時の検出 (`NSDataDetector`。AI ではない) で日時が取れたときだけ予定を作り、取れなければリマインダーかメモに回す形を検討する。日本語でどこまで拾えるかを先に試す。同じ仕組みでリマインダーに期日も付けられる
  - Foundation Models (Apple の LLM) で日時を読む案 (2026-11-13 調べ): watchOS 27 から時計でも使えるが、**時計では Private Cloud Compute (Apple のサーバー) 経由**で、通信と専用の entitlement が要る (初回ダウンロード 200 万未満は無料)。
    時計で動かすと送るたびに待ちが入るので、やるなら**予定・リマインダーを保存する iPhone 側** (端末内のモデル。Apple Intelligence 対応機だけ) で読み、使えない機種は `NSDataDetector` に落とす。
    出典: WWDC26 セッション 241 (https://developer.apple.com/videos/play/wwdc2026/241/)・Developer Forums (https://developer.apple.com/forums/thread/831742)。時計の端末内で汎用の言語モデルが動くかは確かめられていない
- **ショートカット用のアクション** (「最新メモを取得」): 初版では入れない
- **Apple のメモ・ジャーナル・メッセージ**: 裏で書き込む公開 API が無い (共有シート・ショートカット経由のみ)

## 削除

- Hayate 内でメモを消しても、送信済みの Webhook や作成済みのリマインダーには反映しない
- 消すときにそのメモの未送信の連携も取り消す
- 通信・保存が既に進んでいる場合は取り消しが間に合わないことがある (画面の文言でそう伝える)

## 決定 (2026-11-13 ユーザー回答)

- **ライセンス: MIT**。広く使われ、フォーク・流用の障壁が低いことを優先
- **メモの正は iPhone**。時計で入力したメモは全文を iPhone へ送り、iPhone が全件を持つ。時計は直近 50 件。
  後から送信・削除は iPhone で行う。時計で入れた分の自動送信・再送は時計が受け持ち、後から送信は iPhone が送る (どの連携をどちらの端末が送るかを 1 つに決めて二重送信を避ける)
- **リマインダーの合図は 44 言語すべて**。各言語の合図を訳で用意する。音声入力での表記ゆれ (区切りの「、」「,」「:」・空白・区切りなし) を受ける。
  実機の音声入力で確かめられるのは日本語・英語だけで、他の言語は訳の合図のまま出す (問い合わせで直す)
- **合図の表記ゆれ**: 言語ごとに既定の合図を複数持ち (日本語なら「リマインダー」「リマインド」「やること」など)、ユーザーが設定で足したり外したりできる。
  「自由なキーワードルール」(対象外) とは別で、リマインダーへの振り分けの合図を増やせるだけ
- **合図だけで本文が無いとき**: メモだけ保存し、リマインダーは作らない
- **Git 履歴は書き換えずに公開する**。ccpocket (K9i-0/ccpocket、MIT) と同じ形 (2026-11-13 に確認: 2,678 コミットをそのまま公開、作者メールも個人の Gmail のまま、`CLAUDE.md`・`.claude/skills` も公開)。
  作者の Gmail は ccpocket への PR で既に公開されている。公開前に `CLAUDE.md` を誰が読んでも通じる内容に書き直し、時計の UDID・ASC キー ID・非公開 doc (`~/work/docs` 等) への参照を消す。
  過去のコミットには残るが、キー ID だけでは使えず、鍵ファイル・Webhook の URL は履歴に無いので実害はほぼ無いと判断
